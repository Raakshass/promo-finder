# AI tools used, and where they got it wrong

**Tools.** An AI coding agent (with research sub-agents) for requirements analysis, architecture, code, tests, research and documentation, always reviewed and re-checked with code. NVIDIA Nemotron 3.5 Super (open weights, free via OpenRouter) is the scoring, story-arc, cold-viewer and ledger model of the official run, batched five episodes per call to fit a free daily request cap. Tested and not adopted: Qwen3-4B and Llama-3.1-8B run locally (unlimited, private, but slow and weaker), and a trained Hugging Face emotion classifier (no measurable gain).

**Where they got it wrong (kept honestly):**

1. **Confident wrong numbers.** The planning sub-agent reported that "25/50 continuity notes literally say 'picks up from Episode N's cliffhanger'" and "22/50 episodes end with an explicit writer cue". A grep over the pack gives **12** notes that say "cliffhanger" and **23** episodes with an end cue. The design was sound; the evidence it cited was invented in the right shape. Every figure in the solution doc was re-counted with code before use.
2. **A proper-noun drift detector that missed the obvious.** The first version clustered capitalised words on a 4-letter prefix, which split the estate name from its variant spellings and reported nothing, even though 13 spellings of the estate name exist. Fixed by a 3-letter prefix plus a "mid-sentence capital" rule, and verified against the pack (8 spellings with ≥2 occurrences are now listed in the QA report).
3. **The lexicon twin's taste.** With no model, the heuristic ranks a romantic gaze between the two leads as a 3/3 cliffhanger purely because it is the last beat of episode 16. That is the baseline the model has to beat, and the ablation table shows whether it does.
4. **The agent mistook a spending limit for a balance.** OpenRouter's key endpoint reported `remaining_usd: 1`; the agent planned three paid Gemini runs against it and launched two in parallel. The account actually held about 17 cents of trial credit, the runs failed at episode 32 with "can only afford 2906 tokens", and 46 episodes silently fell back to the heuristic twin. Three fixes came out of it: out-of-credit errors now abort a run in one call, concurrency is a flag, and `--batch` cuts a run from ~140 calls to ~25 so it fits request-capped free tiers.
5. **The scoring model thinks a love scene is a cliffhanger.** Nemotron 3.5 gave a tender declaration-of-love line in episode 10 a 3/3 cliffhanger score, and the ranker put that clip first. By the brief's definition a cliffhanger is an unresolved moment; a declaration is a resolution. Fixed with an explicit, documented rule (romance beats cap at 2/3 unless interrupted or left as a question) rather than by editing the output, and the model's original score stays in `beats/ep-010.json`.
6. **A batched answer silently dropped an episode.** In the official run the model's answer for the batch of episodes 6–10 contained no beats for episode 10, so every beat of that episode fell back to the heuristic twin without any error. The run log caught it (`id_issues`), and the fix is an automatic single-episode retry whenever a batch answer omits or empties an episode, recorded in the run log as "re-scored alone". Beat-scoring model errors seen in `run_log.json`: unknown or missing beat ids, JSON repairs, per-episode fallbacks.
7. **The first design was too conservative, and nobody had checked what "good" means.** Version 1 scored every line on its own (a hook score and a cliff score) and joined the best pair. It never asked whether the *clip* had a conflict a stranger could follow, someone to root for, rising stakes, or an ending before its own payoff. Those are the rules ad platforms, micro-drama ad editors and trailer editors actually use. The user pushed back. Four parallel research agents then collected the published standards (`docs/research.md`), and version 2 turned them into the editor's rubric, the spoiler-safe acquisition lane, the promo-ability report and a blind A/B test against version 1. The research agents also overreached in places, e.g. stating "cliffhangers increase binge intent" when the one lab study found they did not. Every claim kept in the doc is tagged evidence or inference, with a source.
8. **The agent leaked the show into a public prompt.** The v1 scoring prompt used a verbatim line from episode 1 as its example of a perfect hook. Test fixtures used two more real lines, and docs used a real action line and character names, all in a public repo whose input pack is confidential. A grep of every tracked file against the scripts caught it during the v2 work. All of them were replaced with invented lines, and the check (`grep` each quoted test/prompt string against `data/`) is now part of the pre-push routine. The earlier commits still contain them; purging history needs the repo owner's approval.
9. **The free scoring model's silent "flat" answers, which the agent's first version trusted.** In batched calls, Nemotron returned an all-zero hook or cliff score for whole episodes (14 of 50 in the v2 run), with valid JSON and no error. The promo-ability report gave it away: a revenge melodrama came out "hard to promo", with episodes whose best hook score was 0. The tool now treats "no line above 1" as a lapse and re-asks that episode alone: 11 were fixed, and 3 were confirmed as quiet and kept. The stability comparison also leaves these episodes out, so it measures consistency, not lapses.
10. **A position-biased judge.** In the blind A/B test, the free judge picked "clip 1" for most pairs in both orders. Showing each pair twice, swapped, turns that bias into ties instead of a fake win, so the honest result is v3 3, v1 2, 5 ties.
11. **A paid model sneaked into a "free" test run.** The `.env` file still named a paid OpenRouter model as the judge, and the CLI used it whenever `--judge-model` was not given, even for a mock run. Two calls cost a fraction of a cent. Fixed: the judge now follows `--model` unless `--judge-model` is set, and `.env` defaults to the free model.
12. **A too-narrow type would have crashed the final write.** New decimal flags (minutes into the show) did not fit the promo model's `bool | int | str` flags type. A 3-episode test caught it before the official run; a regression test now guards it.
13. **The first "where promos come from" rule was a guess.** The first version used three soft lanes (x1.0 / 0.95 / 0.85), so only 4 of the top 10 came from the opening 30% of the show. Measured on 501 professional ads (DramaAD), editors take 55% of footage from the first 20% of episodes. The slate now copies that shape.
14. **The research step overstated a benefit.** A trained emotion classifier (390K downloads) looked like a free, consistent signal; measured, it agreed with the model's line scores less than the keyword list did (0.20 vs 0.32 rank correlation) and added nothing significant (AUC +0.007, 95% CI -0.02 to +0.03). Not adopted.
